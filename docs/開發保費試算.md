## 開發保費試算
---
### 方法一
| 項次 | 工作項目 |  |
| :--- | :--- | :--- |
| 1 | 模組 A：費率自動化 |  |
| 1.1 | 費率 Schema 與維度設計 | 包含計算邏輯 (Lookup/Multiply) 與組合保費結構。 |
| 1.2 | 各司費率解析測試 (PoC) | 以富邦、南山等不同格式測試 AI 提取信心度。 |
| 2 | 模組 B：條款自動化 | 結構化萃取商品條款資訊，建立標準化給付資料庫，支援未來前端動態渲染與精準需求比對。|
| 2.1 | 蒐集資訊與語義對齊 | 避免 AI 在解析時自創名詞,導致前後端無法用同一套範本處理 |
| 2.1.1| 前處理：掃描條款建立 Standard Tag 與 Synonym Map。 | 目前偏向全自動/半自動 |
| 2.2 | 給付項目公式化 | 把條款從閱讀用變成試算用,當限額1萬定義成limit:10000,試算工具才能利用數字進行計算 |
| 2.2.1 | 將法律條文轉化為 Amount, Limit, Condition 的 JSON 結構。 |  |
| 2.3 | 實作條款提取 Prompt | 將上述的定義實現 |
| 2.3.1 | 訓練 Agent 定位條款區塊並產出結構化 Benefit JSON。 | 提示工程+同義詞查找,製作出可用的結構化商品資料 |
| 3 | 模組 C：管理後台與展示 | (工程實作) |
| 3.1 | 商品資訊編輯器 | 包含費率預覽、給付項目人工校對功能。 |
| 3.2 | 動態渲染引擎 | 前端直接讀取 JSON 渲染試算結果與保障內容。 |

## 直接透過NoteBookLM管理商品&提問
---
### 側重: 資料同步處理管線
* 包含
  * 商品版控: 保發中心更新XX商品第X次修正內容時同時更新資料
  * 商品資訊聚合: -F -A -C合成同一份文件(避免佔用文件數量上限)同時可以一起檢索內容。
  * 資料存放位置與串接資料來源: NoteBookLM可以直接使用GoogleDrive匯入資料來源,或是使用企業版API
